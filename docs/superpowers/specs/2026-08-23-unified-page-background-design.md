# Bitpongo 全局页面背景统一设计

## 背景

当前前端页面没有统一的画布背景契约：大部分页面继承浏览器或组件库的白色背景，未登录“我的”页单独使用品牌暖白 `#FFFAF5`，布局导航区域也未显式与页面画布保持一致。这会让页面切换时产生明显色差，并使新增页面容易再次偏离。

本设计只作用于 `/Volumes/ExternalDrive/Code/github/bitpongo-front`，不修改 `zhitoubao` 或其他仓库。

## 目标

- 所有页面画布统一使用品牌暖白 `#FFFAF5`。
- 顶部导航栏、页面滚动容器和底部标签栏与页面画布保持一致。
- 新页面默认继承统一背景，不需要逐页重复声明。
- 卡片、输入框、弹窗、提示、图表、按钮和状态区域保留自身功能性背景。

## 非目标

- 不把所有元素强制改成同一背景色。
- 不改变品牌橙色主视觉、错误/警告颜色或图表颜色。
- 不调整布局、间距、字体、路由或业务逻辑。
- 不修改移动端原生资源或离线包；离线包同步属于后续独立发布步骤。

## 方案

在全局样式中新增唯一语义变量：

```scss
:root {
  --app-page-background: #fffaf5;
}
```

将该变量应用到以下页面级承载层：

- `html`
- `body`
- `#app`
- 基础布局的 `.main-page`
- NutUI 顶部导航栏与底部标签栏对应的背景变量或容器

页面级容器默认保持透明并继承画布。未登录“我的”页现有 `#FFFAF5` 声明改为使用全局变量，避免出现第二个颜色来源。

## 背景边界

“页面背景”指应用最外层画布和固定导航区域，不包括内容组件。以下背景继续保留：

- 白色内容卡片、表单项和弹窗
- 登录错误提示、账户删除警告等状态区域
- 品牌橙色渐变英雄区和按钮
- 图表、截图容器、币种分布和策略状态颜色
- 透明按钮或输入控件的交互背景

因此实现不得通过 `*`、所有 `div` 或所有组件类的强制选择器覆盖背景。

## 测试策略

新增背景契约测试，真实编译全局 SCSS，并验证：

1. `--app-page-background` 的计算值为 `#FFFAF5`。
2. `html`、`body`、`#app` 和 `.main-page` 使用同一语义变量。
3. 顶部导航栏和底部标签栏映射到同一页面背景。
4. 未登录“我的”页不再写死第二份页面背景色。
5. 代表性白色卡片和错误提示仍保留自身背景，防止全局覆盖过宽。

验证同时运行类型检查、样式检查、相关组件测试和生产构建。现有注册页边框断言如果仍是唯一基线失败，应单独报告，不得误称完整测试全绿。

## 验收标准

- 在登录、注册、策略列表、策略详情、个人中心及其子页面间切换时，页面空白区域和固定导航区域均为 `#FFFAF5`。
- 页面滚动或内容不足一屏时，不出现白色或透明底色断层。
- 卡片和功能性状态背景没有被统一画布规则覆盖。
- 全局仅保留一个页面背景颜色来源，后续修改只需调整语义变量。
