# 注册表单可见性修复设计

## 背景与根因

注册页已经渲染昵称、邮箱、密码和确认密码四个 `nut-input`，生产构建产物中也包含这些组件。问题来自页面局部样式和现有构建配置的组合：项目 PostCSS 按 750px 设计稿将业务源码中的 `px` 转换为 `vw`，因此注册页声明的 `14px` 在 375px 视口中实际约为 7px。与此同时，`nut-form-item` 没有明确边框或对比背景，输入框主要依赖占位文字提示，在白色页面上容易被误认为没有输入框。

现有组件单元测试用原生输入框替身代替 NutUI 组件，只验证注册流程，没有覆盖真实样式，因此未发现该问题。

## 方案比较

### 方案 A：注册页局部修复（采用）

- 注册页字号和间距改用 `rem`，避开 750px 的 `px` 转换。
- 为四个字段增加明确的可见标签。
- 为表单项增加边框、背景和聚焦状态。
- 保留现有占位文字、校验、提交和错误处理逻辑。

优点是修改范围小、风险低，并能直接解决字号和输入框可见性问题。缺点是其他页面仍沿用现有 750px 样式规则，需要以后逐页治理。

### 方案 B：全局把业务源码设计宽度改为 375px

能从构建层统一修正字号缩半问题，但会同时放大现有所有业务页面的尺寸，必须进行完整视觉回归。本次不采用。

### 方案 C：继续使用 `px`，把注册页数值全部加倍

短期能抵消转换比例，但代码中的数值不再代表真实 CSS 尺寸，维护者容易再次写错。本次不采用。

## 页面设计

注册页继续使用单列移动端布局。标题采用约 28px 的视觉字号，副标题和正文不小于 14px，输入内容采用约 16px。每个字段显示独立标签，输入区域使用白色背景、浅灰边框和圆角；获得焦点时边框变深并显示轻微焦点环，确保用户能清楚识别当前输入位置。

字段顺序保持不变：昵称、邮箱、密码、确认密码。密码规则提示仍紧邻密码字段。协议、注册按钮和登录入口保留现有交互，但正文调整为正常可读字号。

## 组件与国际化

修改 `src/views/register/index.vue`：

- 使用 NutUI 表单结构承载字段。
- 为四个 `nut-form-item` 绑定国际化标签。
- 添加注册页专用样式类，避免影响登录页和其他 NutUI 表单。
- 使用 `rem` 表达页面局部字号、间距、圆角和边框。

修改 `src/i18n/lang/lang-base.ts`、`zh-cn.ts`、`zh-tw.ts` 和 `en-us.ts`，新增以下键：

- `register.nameLabel`
- `register.emailLabel`
- `register.passwordLabel`
- `register.confirmPasswordLabel`

## 数据流与错误处理

注册数据流不变：输入通过 `v-model` 写入现有响应式表单，`canSubmit` 继续检查昵称、邮箱格式、密码强度、两次密码一致性和协议勾选，提交仍调用 `userStore.register`。后端错误继续显示在表单内，输入内容继续保留供用户修正。

本次不修改 API、路由、状态管理、注册校验规则或后端。

## 测试与验收

采用测试先行：

1. 先扩展注册页组件测试，要求页面渲染四个可见字段标签和四个注册字段容器；在实现前测试应失败。
2. 实现标签和局部样式后，注册页测试应通过，原有注册成功、密码校验和错误重试测试继续通过。
3. 运行前端完整单元测试、类型检查和生产构建。
4. 检查生产 CSS，确认注册页关键字号保留为 `rem`，输入字段包含可见边框规则，不再生成约 7px 的正文。

验收标准：在 375px 移动视口中，标题、说明、协议和登录入口清晰可读；四个输入字段无需依靠占位文字也能被识别；聚焦状态明显；现有注册行为没有变化。
